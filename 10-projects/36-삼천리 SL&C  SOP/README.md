# 삼천리 SL&C 브랜드별 SOP — 직원 교육 앱

매장 교육자료(PPTX)를 **목차 순서 그대로** 옮긴 웹앱. 직원이 **개인 스마트폰**으로 학습하고 이수를 표시한다.
1차 대상은 **KSC(Kalbi Social Club)** 와 **WASA(Izakaya Wasa)**.

배포: https://comimi12.github.io/slnc-sop-dashboard/

## 무엇이 들어있나

| 브랜드 | 문서 | 분량 |
|--------|------|------|
| KSC | 입문 · 서비스 매뉴얼 | 47p / 8개 챕터 |
| KSC | 입문 매뉴얼 (간소화) | 18p |
| KSC | 메뉴 SOP | 54종 (사진 37종) |
| WASA | 입문 · 서비스 매뉴얼 | 48p / 8개 챕터 |
| WASA | 메뉴 SOP | 91종 (사진 87종) |

원본 이미지 184장을 웹용(긴 변 1000px)으로 재인코딩해 포함.

## 입문 매뉴얼 (간소화)

휴대폰으로 훑는 교육이라 전체 매뉴얼(49~52p)이 아니라 꼭 필요한 장만 순서대로 남겼다.
구성은 `src/app.js`의 `COURSE` 배열 한 곳에서 정한다 — 항목을 더하거나 빼려면 여기만 고치면 된다.

| 묶음 | 항목 |
|------|------|
| 브랜드 · 매장 | 브랜드 소개, 우리 매장 정보 |
| 기본 기준 | 용모 · 복장 기준, 직급별 역할 |
| 내 포지션 | 선택한 직급의 표준 절차 1장 |
| 서비스 | 서비스 10단계, 상황별 응대, 컴플레인 응대 |

두 브랜드 모두 8개 항목(내 포지션 포함). 오픈·마감 체크리스트는 **체크리스트 탭**에 따로 있다.

**뺀 것** (제목 기준, 두 브랜드 동일): 표지·목차, 매뉴얼 사용법, 서비스 철학,
보고 체계, 1일 운영 리듬, 관리자 SOP(CH.05) 전체, 응대 스크립트 ①②,
서비스 10원칙, 교육 로드맵, 오픈·마감 체크리스트,
**안전·법규 5장**(주류·알러지·위생·비상·근로법규), **참고 자료**(메뉴별 알러지 표, 메뉴 지식 ①②).

> 뺀 장도 `src/data.json` 에는 그대로 남아 있다. 되살리려면 `COURSE` 에 항목을 다시 넣으면 된다.
KSC에만 있는 장을 지운 것이 WASA의 같은 번호 장에 잘못 적용되지 않도록,
삭제는 순번이 아니라 **원본 제목**으로 판단한다.

본문에서는 제목 없는 긴 도입 문단만 뺀다. 영문·국문은 항상 함께 보여준다
(미국 매장이라 두 언어가 모두 필요하다).

### 화면 문구

앱의 모든 문구는 **영문 위 / 국문 아래**로 함께 보여준다. `L(en, kr)` 헬퍼가 두 줄 라벨을 만든다.

### 그릴 영상 (KSC)

원본은 `Desktop\교육팀\9. AI영상\미국\KSC\완료\` 의 8K HEVC 3편(합계 1.5GB)이다.
그대로는 GitHub 파일당 100MB 한도를 넘고 HEVC라 브라우저에서 재생도 안 된다.
`build/videos.py`가 **720p H.264 + faststart**로 변환하고 포스터 이미지를 뽑는다.

인코딩은 `ENC` 한 곳에서 관리한다. 순수 CRF는 구간마다 3.4Mbps까지 튀어
약한 회선에서 멈추므로 `-maxrate 1800k -bufsize 3600k` 로 천장을 두고,
`-g 60`(2초 GOP)으로 시작·탐색을 빠르게 한다.

```bash
python build/videos.py       # src/video/*.mp4 + *.jpg + index.json
```

**우대갈비 서비스 가이드**는 영상 파일이 아니라 HTML 합성물이 원본이다
(`Downloads\우대갈비 영상 편집 (4)\…(오프라인 재생).html` — 1920x1080 무대에서
클립 2개와 자막을 타임라인으로 돌린다). `build/woodae.py` 가 mp4로 만든다:

```bash
python build/woodae.py          # 소스 H.264화 → 60초 화면 녹화 → 오디오 합성 → mux
python build/woodae.py --reuse  # 녹화본 재사용하고 다시 합치기만
```

- **끊김의 원인**: 원본 HTML은 클립을 1배속으로 재생하면서 타임라인이 요구하는
  위치와 0.34초 이상 벌어지면 되감는다. 타임라인은 소스를 0.79~0.10배속으로
  느리게 요구하므로 재생이 매초 0.2초씩 앞서고 **약 1.6초마다 뒤로 튕긴다**.
  화면 녹화를 하면 이 튕김이 그대로 찍힌다.
  → **클립을 미리 타임라인 배속대로 늘려 두고**(setpts/atempo) HTML은 1:1 재생만
  하게 고쳤다. 되감기 25초당 11회 → 1회.
- vB는 구간마다 배속이 다르다(0.95배 / 0.64배 / 끝 6초는 10배 슬로우) — 구간별로
  늘린 뒤 concat 한다
- 크로미움이 HEVC를 못 열어 검게 녹화되므로 소스를 먼저 H.264로 바꾼다
- 녹화는 페이지가 그려지기 전 흰 화면부터 시작하므로, 첫 실제 프레임을 찾아 잘라낸다
- 오디오는 화면 녹화로 못 잡아, 배속까지 맞춰진 클립에서 따로 꺼내 합친다

**꽃살 그릴 스탠다드**도 HTML 합성물이 원본이다
(`Downloads\export\꽃살 그릴 교육영상.dc.html` — 1920x1080 무대에서 클립 8개와
자막을 60초 타임라인으로 돌리는 React 합성물). `build/kkotsal.py` 가 mp4로 만든다:

```bash
python build/kkotsal.py          # 클립 H.264화 → 1800프레임 캡처 → 인코딩 (10분 안팎)
python build/kkotsal.py --reuse  # 캡처본 재사용하고 다시 인코딩만
```

- 우대갈비와 달리 **실시간 녹화를 하지 않는다**. 이 합성물은 호스트가 프레임 단위로
  장면을 요구하는 통로(`data-om-seek-to-time-frame`)를 이미 갖고 있어서,
  t를 1/30초씩 밀며 한 장씩 찍는 편이 정확하다 — 프레임 드랍도, 흰 화면 잘라내기도 없다
- 찍기 전에 `performance.now`를 얼려 합성물의 자체 재생 루프를 멈춘다.
  얼리지 않으면 마지막 seek 400ms 뒤 루프가 다시 돌아 화면과 자막이 어긋난다
- 클립 8편도 HEVC라 크로미움이 못 연다 — 먼저 H.264로 바꾼다
- **소리는 따로 얹는다**. 원본 합성물은 클립을 muted 로 깔지만, 클립에는 8단계를 안내하는
  **영어 내레이션**과 현장 그릴 소리가 들어 있다

#### 내레이션을 자막에 맞추기

내레이션은 클립 경계와 따로 논다 — 점화 안내는 `02-temp`에, 온도 안내는 `03-oil` 끝에 있고,
`01-ignite`·`05-sear`에는 말이 아예 없다. 그래서 **합성물의 화면 in/out 지점을 그대로 소리에
쓰면 안 된다**. 그렇게 했더니 문장이 중간에서 잘리고, 2번 장면(온도 체크) 위에 점화 안내가
얹히고, 4번 장면은 정작 제 안내("한 줄로 겹치지 않게")가 통째로 잘려 나갔다.

`VO` 는 내레이션을 **문장 단위로 잘라 자막에 맞는 장면에 놓은 표**다. 말이 없는 구간은
화면만 돌아 허전하므로, 클립에서 **말이 없는 부분만** 모아(`BED`) 낮게 깔았다 —
내레이션과 겹쳐도 같은 말이 두 번 들리지 않는다. 구간마다 녹음 레벨이 달라
(-22~-29dB) 내레이션은 -20dB, 앰비언스는 -34dB로 각각 맞춘 뒤 리미터를 건다.
제목(0~3초)과 닫는 카드(56~60초)는 무음.

> 손댔으면 **자막 구간별로 다시 전사해 확인**한다. 8개 구간에 제 안내가 들어갔는지는
> 귀로 듣지 않고도 `faster-whisper` 로 구간을 잘라 전사하면 바로 보인다.

- 원본 `export` 폴더는 한 번 쓰고 지워진다. 그 뒤에는 `build/_kkotsal/clips/` 의
  H.264 사본(소리 동일)으로 계속 돌아간다 — 이 폴더는 git에 올리지 않으므로,
  지워졌다면 합성물을 다시 내보내야 한다

영상 목록·설명은 `build/videos.py`의 `VIDEOS` 에서 관리한다
(`file=None` 이면 다른 스크립트가 만든 영상으로 보고 변환을 건너뛴다).
서비스워커는 `/video/` 를 캐시하지 않는다 — Range 요청(206)은 캐시에 넣을 수 없어서다.

### 메뉴 탭 흐름

탭을 열면 **사진이 바로 보이도록** 전 분류를 한 페이지에 펼친다(한 번 더 들어가지 않음).
대신 **완료 버튼을 각 분류 카드 바로 아래**에 두어 무엇에 대한 이수인지 분명하게 한다 —
예전처럼 전체 보기에는 버튼이 없고 분류를 골라야만 나타나면 어디를 눌러야 할지 알기 어렵다.

- `#/menu` — 얇은 진도 줄 + 분류 칩(누르면 해당 분류로 스크롤) + 분류별 [사진 그리드 + 완료 버튼]
- `#/menu/<deck>/<분류>` — 한 분류만 보는 딥링크 (수료 화면의 "이어서 학습"이 여기로 온다)
- 사진은 lazy-load — 90종이어도 첫 화면은 보이는 만큼만 받는다

분류 국문 이름은 `app.js` 의 `CAT_KR` 에서 관리한다.

### 메뉴 사진

원본 사진이 세로·가로가 섞여 있어 `object-fit: cover`로는 음식이 잘렸다.
카드와 상세 팝업 모두 `contain`으로 담아 **전체가 보이게** 한다(남는 자리는 배경색).
카드 비율은 4:3, 상세 팝업도 4:3.

### 속도

첫 화면 0.6MB · 메뉴 탭 1.0MB (이전 1.1MB / 3.7MB). 손댄 곳은 두 가지다.

1. **한글 웹폰트 제거** — Noto Sans KR 4종은 CSS만 369KB에 폰트 파일까지 받아오며
   첫 렌더를 막았다. 한글은 기기 기본 글꼴(맑은 고딕 / Apple SD Gothic Neo), 영문만 Archivo.
2. **메뉴 카드용 축소본** — 카드는 180px로 보이는데 원본은 1000px·평균 115KB였다.
   `build/thumbs.py`가 360px 축소본(`src/img/t/`)을 만들고 카드만 그것을 쓴다 (21.2MB → 3.3MB).
   상세 시트와 SOP 본문 사진은 원본 그대로.

원본 이미지를 새로 추출했다면 `python build/thumbs.py`를 다시 돌려야 한다.

### 브랜드명

**로바타 와사는 1호점이고, 이 SOP의 매장은 이자카야 와사(IZAKAYA WASA)다.**
원본 교육자료의 `ROBATA WASA` 표기는 `build/extract.py`의 `RENAME`에서 일괄 정정한다.
조리 방식·메뉴 분류로 쓰인 `ROBATA` / `로바타`(로바타에 구운 …)는 그대로 둔다.

인사말도 같은 `RENAME`에서 정정한다 — `Irasshaimase` → `Hello`, `이랏샤이마세` → `안녕하십니까`.

### 생선 이름 (WASA)

원본은 국문 표기에 일본어 음차를 썼다(하마치·토로·우니·이쿠라·에비·타마고·우나기·알바코어).
`build/extract.py`의 `FISH`에서 **한국 생선 이름**으로 바꾼다 — 방어·참치 뱃살·성게알·연어알·
새우·계란·장어·날개다랑어. 조사가 붙는 자리(`토로는`→`참치 뱃살은`)는 받침이 달라지므로
긴 형태를 먼저 두고 치환한다. `FISH`는 WASA 덱에만 적용한다.

## 교육 이수 시스템

서버도 로그인도 없다. 기록은 **그 휴대폰 안**(localStorage)에만 남는다.

1. **내 정보 등록** — 이름 + 연락처 뒤 4자리 + 포지션 (동명이인 구분용)
2. **필수 코스 자동 구성** — 간소화 과정 + 메뉴 카테고리 전부
3. **학습 완료 체크** — 페이지 하단 버튼. **최소 학습 시간을 채워야 열린다** (아래)
4. **트레이너 서명** — 전 항목 완료 시에만 활성화. 손가락 서명 + 담당자 이름
5. **확인코드 6자리** — 이름·포지션·완료수·서명일로 생성. 매니저가 대조
6. **매니저에게 보내기** — 보고 본문 + **등록 링크**를 카톡 등으로 전송

서명 후 학습 항목을 바꾸면 서명이 **자동 무효 처리**되어 다시 받아야 한다.

### 학습 시간 (스크롤만 하고 완료를 눌러 버리는 것 막기)

완료 버튼이 그냥 눌린다면 이수 기록은 아무 뜻이 없다. 그래서 항목마다
**화면에 머문 시간**과 **스크롤 도달률**을 재고, 둘 다 채워야 버튼이 열린다.

- **최소 시간은 분량이 정한다** — 실제로 그려진 글자 수 ÷ 14 + 사진 수 × 4초,
  한 항목당 20~120초. 전 과정을 다 채우면 **약 24분**(입문 8장 13.5분 + 메뉴 16분류 10분)
- 시간은 **화면이 보이는 동안만**, 그리고 **1분 넘게 손이 멈추면** 세지 않는다.
  켜 두고 자리를 뜬 시간까지 학습으로 잡히면 숫자가 의미를 잃는다
- 못 누르는 이유를 버튼 아래에 바로 보여 준다 (`조금만 더 읽어 주세요 · 1분 59초 남음`)
- 메뉴 탭은 전 분류가 한 화면에 있으므로, **지금 화면 한가운데 있는 분류**에만 시간이 쌓인다
- 수료 화면에 **항목별 표**가 나온다. 보고에는 합계가, 등록 링크에는 항목별 초가 실린다

기준은 `app.js` 의 `needOf()` 한 곳에서 정한다. 재기만 하고 막지 않으려면
`gateOf()` 의 `ok` 를 항상 참으로 두면 된다.

### 이수확인 화면 (`#/admin`)

**링크로 등록(기본)** — 직원이 보낸 카톡 메시지의 **등록 링크**를 매니저가 누르면
`#/add/…` 화면이 열리고, 확인 후 버튼 한 번으로 팀 현황에 들어간다. 복사·붙여넣기가 없다.
수료 내용을 base64로 링크에 실어 보내므로 **서버도 계정도 필요 없고**, 항목별 학습 시간까지 따라온다.

**붙여넣기(예전 방식)** — 링크가 없는 보고는 그대로 붙여넣으면 된다. 여러 건을 한꺼번에 넣어도 건별로 잘라 읽는다.

- 확인코드를 **다시 계산해 대조** → 이름·진도·서명일을 고치면 `코드 불일치`로 잡힌다 (코드의 씨앗이 보고서 본문에 전부 들어 있기 때문)
- 수료로 세는 것은 **코드가 검증된 보고만**
- 학습 시간이 **항목당 25초 미만**이면 `짧음`으로 표시하고, 시간 칸을 누르면 항목별 내역이 열린다
- `현황 표 복사` → 엑셀에 바로 붙여넣는 TSV (학습시간 열 포함)
- 같은 사람(브랜드+이름+포지션)의 보고가 다시 들어오면 갱신

이 현황도 **그 기기에만** 저장된다. 여러 매니저가 실시간으로 공유하려면 공용 저장소가 필요하다(아래 확장 참고).

> 링크가 길어 카톡에서 잘리면 등록 화면이 "읽을 수 없는 링크"라고 알려 준다.
> 항목이 지금보다 크게 늘면(현재 23개 · 링크 약 460자) 항목별 시간을 빼거나 묶어야 한다.

## 원본이 DRM으로 잠겼을 때

이 PC는 Fasoo DRM이 걸려 있어 원본 PPTX가 재암호화되면 `extract.py`가
`PackageNotFoundError`로 실패한다. 이때 텍스트 치환 같은 후처리는 이미 뽑아둔
`src/data.json`에 직접 적용하면 된다:

```python
import json, io, sys; sys.path.insert(0, 'build')
from extract import fix_names
d = fix_names(json.load(io.open('src/data.json', encoding='utf-8')))
io.open('src/data.json', 'w', encoding='utf-8').write(json.dumps(d, ensure_ascii=False, separators=(',', ':')))
```

## 우리 매장 정보 (STORE FACT SHEET)

원본 입문매뉴얼의 이 페이지는 **빈칸 서식**이라 data.json에도 질문만 있고 답이 없다.
매장이 작성한 `매장 정보.pptx`(1장 KSC / 2장 WASA)를 읽어 답을 채우는 것이 `build/store_info.py`다.

- 답이 `X`(해당 없음·미정)인 항목은 **질문째로 지운다** — 빈칸을 남겨 두면 직원이 외울 것을 못 고른다.
- 안내 응대 멘트도 같은 기준: 정보가 지워진 주차·화장실 멘트는 빼고, 주방 마감 멘트의 `____`는 라스트콜 답에서 채운다.
  영문 문장에는 한글 시각 표기를 넣지 않는다 — `app.js`의 `pairLines`가 첫 한글에서 줄을 나눠 문장이 반토막 난다.
- 원본 PPTX가 DRM으로 잠기면 스크립트 안 `FALLBACK` 사전을 고쳐 `--fallback`으로 돌린다.

```bash
python build/store_info.py            # 매장 정보.pptx 읽어 반영
python build/store_info.py --fallback # PPTX 없이 사전값으로 반영
```

2026-09-23 반영: KSC 16개 항목 채움·6개 삭제 / WASA 14개 채움·8개 삭제.

같은 날 원본이 **`…_매장정보반영.pptx`**로 바뀌었다 — 답이 라벨 옆 별도 텍스트박스로 들어 있어,
추출하면 답이 줄 없는 블록으로 따로 나온다. `store_info.py`가 그런 블록(과 삭제된 질문이 답에 붙은 블록)을
버리고 라벨 블록에 답을 채우므로 절차는 그대로다.

## 갱신 방법

```bash
python build/extract.py                        # 원본 PPTX 다시 추출
python build/store_info.py                     # 매장 정보(FACT SHEET) 채우기 — extract 뒤에 항상
python build/thumbs.py                         # 메뉴 카드용 축소본 생성
python -m http.server 8766 --directory src     # 로컬 확인
python build/verify.py 8766                    # 화면 자동 검증
python build/verify_study.py 8766              # 학습 시간 게이트 + 등록 링크 검증
python build/deploy.py                         # 배포
python build/verify.py https://comimi12.github.io/slnc-sop-dashboard/   # 배포본 검증
```

`extract.py`는 원본 덱이 생성기로 만들어져 도형 배치가 일정하다는 점을 이용한다.
레이아웃을 크게 바꾼 PPTX를 넣으면 추출 규칙(카드 밴드 폭, `CL_*` 도형 이름, 챕터 푸터 `CH.0n`)을 함께 손봐야 한다.

브랜드 추가는 `build/extract.py` 상단 `DECKS`에 항목 추가 (`kind`는 `manual` 또는 `menu`).
